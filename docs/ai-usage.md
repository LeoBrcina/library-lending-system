## Purpose and reporting rules

This document records how AI tools were used during the development of the P03 Library Lending System. It summarizes the tasks for which AI assistance was requested, the suggestions provided, the changes made by the developer and the methods used to verify the results.

AI-generated suggestions and code are reviewed before being accepted. All implementation and testing results documented here are based on actual development activities.

## Usage entries

### AI-001 — Interpret P03 requirements and plan milestones

- **Date:** M1 planning phase (documented on 2026-10-29).
- **Prompt/task summary:** Review the professor's P03 Library Lending System requirements and propose a compliant Spring Boot architecture and milestone plan.
- **AI contribution:** Structured the required title/copy/loan/member and reservation domain, security, persistence, REST/API, AI, testing, internationalization, scheduler, deployment and documentation work into milestone-sized tasks.
- **Developer contribution:** Chose the public-library scope, hybrid physical checkout/return, member dashboard and stepwise development and commit workflow; required the official assignment to be treated as authoritative.
- **Changes and rationale:** The plan was narrowed to a public library with staff-managed physical circulation, rather than an unrestricted self-service borrowing system, to reflect the chosen real-world workflow. The developer also required one verified milestone step at a time to keep the project explainable.
- **Evidence/verification:** The project plan and subsequent ERD/ADR discussions were reviewed conversationally. Professor approval of the topic has not been independently confirmed.
- **Affected artifacts:** Planning decisions captured in `docs/decisions.md` and `docs/adr/001-persistence-model.md`.

### AI-002 — Define business policies and logical data model

- **Date:** M1 design phase (documented on 2026-10-29).
- **Prompt/task summary:** Design the library business rules and build the ER diagram incrementally in draw.io.
- **AI contribution:** Proposed fields and relationships for 12 tables; explained attributed many-to-many associations, optional foreign keys, loan constraints, reservation allocation and daily fine accrual records.
- **Developer contribution:** Accepted or refined the 21-day loan, two 14-day renewals, five-loan limit, €0.20-per-day fines, three-day reservation pickup deadline and nonblocking unpaid fines; manually created and reorganized the draw.io diagram.
- **Changes and rationale:** The developer selected concrete loan, renewal, fine and reservation policies from the alternatives discussed, required borrower and issuing/returning staff to be recorded separately and chose to prioritize functional correctness over further visual polishing of the ER diagram. The diagram was drawn by the developer, not automatically generated by AI.
- **Evidence/verification:** The developer supplied diagram screenshots during the review. The `.drawio` and PDF files were saved and committed. No PostgreSQL application tables or constraints had been created or tested at this stage.
- **Affected artifacts:** `docs/diagrams/LibraryLendingSystem_ERD.drawio` and its PDF export.

### AI-007 — Configure PostgreSQL through Docker Compose

- **Date:** 2026-10-29.
- **Prompt/task summary:** Run an isolated PostgreSQL instance through Docker Compose without committing credentials or disturbing older containers.
- **AI contribution:** Proposed `postgres:17`, a named volume, a health check, host-only port `5433`, `.env.example` and Git ignore rules for secrets.
- **Developer contribution:** Created `compose.yaml`, `.env.example` and local `.env`, adjusted `.gitignore`, launched the container and performed the SQL check. Subsequently identified that the actual database password had also been placed in `.env.example`.
- **Changes and rationale:** The database was bound to `127.0.0.1:5433` instead of exposing port 5432 broadly, and existing Docker resources were preserved. The developer corrected `.env.example` to use a placeholder and chose to rewrite Git history to remove the original password from the active branch history.
- **Evidence/verification:** `docker compose config --quiet` passed; `docker compose ps` reported `library-postgres` healthy; a `psql` query returned database `library_lending`, user `library_app` and PostgreSQL 17.11. The rewritten Docker configuration commit is `0001f35`. Verification confirmed that `.env.example` contains a placeholder in the rewritten branch history. The password was not rotated, and the rewrite does not guarantee removal from all previously retained copies.
- **Affected artifacts:** `compose.yaml`, `.env.example`, `.gitignore`; local `.env` intentionally untracked.

### AI-010 — Evaluate and select the AI provider

- **Date:** 2026-10-29.
- **Prompt/task summary:** Compare AI providers for the P03 purchase-suggestion feature, recheck the professor's exact AI requirements and determine whether a free-tier Gemini model could handle the task reasonably.
- **AI contribution:** Compared Google Gemini, OpenAI, Anthropic Claude and alternative inference approaches. Reviewed the required classification, duplicate detection, human confirmation, testing and evaluation workflow. Recommended Google Gemini because the task involves relatively small amounts of text and structured output, and eligible free-tier models may be sufficient.
- **Developer contribution:** Requested a second examination of the official assignment before deciding and explicitly prioritized a practical, reasonably capable model over maximum AI performance. Accepted Google Gemini as the project provider.
- **Changes and rationale:** The initial broad provider comparison was narrowed to the precise P03 requirements. The selected workflow uses the member's suggestion, predefined subject categories and relevant existing catalog candidates as AI input. The final provider decision was separated from the exact model choice so that model availability, quota and response quality can be verified later.
- **Evidence/verification:** The provider decision was accepted during M1 planning. No Gemini API key, live inference result, quota test, model accuracy measurement or deployed AI integration has yet been verified.
- **Affected artifacts:** `docs/decisions.md` (D-029 and D-039 through D-046); ADR-002 and `docs/ai-evaluation.md` planned for later milestones.
